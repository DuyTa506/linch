# WP8 hot-path measurements

Scale tables are medians of three interleaved pairs; profile tables are single
lean runs. The baseline is the production-shaped runtime at 47c17d3; each step
compares only the source change named in that step. Memory cases use the in-memory
stores; Postgres cases use the configured production backend. cycles is asyncpg
protocol exchanges per provider turn; memory has no SQL cycle count. Bytes are
UTF-8 JSON payload bytes written by the checkpoint, event, and session append
paths.

Step 5 retains the `7125522` harness on one side and compares it with the new
harness; only the SDK report alias changed outside the hot path. The final
47c17d3 comparison uses the current harness on both source snapshots.

## D15 - checkpoint codec prototype

The prototype encoded one checkpoint type at the Postgres call site used by all
writes; hand-written validation, deterministic fingerprints, and wire version 3
stayed unchanged. Workload process time excluded setup/teardown and lean byte
accounting was disabled. CPU reductions were 0.37% and 0.42% in memory
negative controls, and 0.52% and 0.19% in Postgres. It was dropped: below the
10% gate and the 5% stop threshold.

After step 3, memory 200 x 4 still spent 2.814 seconds self-time in
_json_safe_inner (4.839 seconds cumulative; 24.55% self-time). The duplicate
checkpoint_to_dict traversal fell from 9,200 to 4,600 calls in step 4; the
remaining profile has deepcopy at rank 1, _json_safe_inner at rank 2 for memory
200 x 4, rank 1 for Postgres 200 x 4, and rank 3 for Postgres 1 x 50. D15 was
dropped after its sub-1% CPU result; no codec shipped.
