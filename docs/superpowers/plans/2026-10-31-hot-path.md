# WP8 hot path implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Increase concurrent run capacity and remove avoidable history-dependent turn work, with measured evidence for every change.

**Architecture:** Retain write-through durability and detached projection reads. Measure production Postgres and memory first; use profiles to choose checkpoint, history, and phase batching changes. Adopt codec changes only if the measured threshold is met.

**Tech Stack:** Python 3.11+, asyncio, asyncpg, pytest, cProfile.

**Spec:** `docs/superpowers/specs/2026-10-30-scale-ready-architecture.md` (WP8, D15), plus the worker's ordered seven-step brief.

## Global Constraints

- Stay on `scale/hot-path`; never push or edit other worktrees.
- Durable before side effects; no write-back caching of sessions, checkpoints, events or permission decisions.
- Getters return deep-copied, read-only projections.
- Success events remain byte-identical after normalization; fingerprints remain deterministic; wire version stays 3.
- No process-global mutable state or new public names unless necessary and explained.
- TDD for behavior changes; interleaved previous/current measurements, three samples each, medians.
- Each logical commit ends with `Co-Authored-By: Codex <noreply@openai.com>`.

## Review Focus

- Interrupted tool execution must resume from a consistent durable checkpoint/event cursor.
- Lease loss must fence atomic batches without writing either component.
- Incremental fingerprints must equal cold-load fingerprints, including empty histories and nested metadata.
- Returned projection mutation must never affect later reads, digest state, or canonical entries.
- Optional capability fallback must preserve custom store failure behavior.
